# 编译原理实验：从词法扫描到语法分析

用 C++ 实现课程中的词法分析、预测分析和 LR(0) 分析过程，并保留输入文法、测试程序及历史输出。适合沿着“输入字符 → 单词符号 → 文法集合 → 分析表 → 分析过程”阅读代码。

这是课程实验集合，各实验分别编译运行；PL/0 和语义检查练习用于学习编译流程，并非完整 C/C++ 编译器。

## 可以查看什么

| 实验 | 入口 | 核心内容 |
| --- | --- | --- |
| 词法分析 | `Experiment11.cpp`、`Experiment1.cpp` | 关键字、标识符、数字及运算符识别，输出 token 或错误信息 |
| 预测分析 | `Experiment2.cpp` | 可空非终结符、FIRST / FOLLOW / SELECT 集、预测分析表与输入串分析 |
| LR(0) 分析 | `Experiment3.cpp` | 项目集规范族、分析表和移进/归约过程 |
| 递归下降练习 | `Experiment4/main.cpp`、`pl0.h` | PL/0 风格的符号表、声明与语句分析 |
| 语义检查练习 | `Experiment4.1.cpp` | 基于文本规则检查变量、函数与类型错误，保留课程实现的局限 |
| 表达式转换 | `Experiment4.4.cpp` | 使用运算符栈将中缀表达式转为逆波兰表达式 |

`实验代码/` 保留按实验编号组织的副本，根目录是下方命令使用的入口。其他零散源文件是历史练习，不属于统一编译流水线。

## 环境与构建

原项目使用 Windows 上的 Visual Studio / Dev-C++。部分源文件采用 GBK 编码，使用 GCC 的 `bits/stdc++.h`；不要将所有 `.cpp` 一次性链接，它们各自有 `main()`。

使用 **Windows + MinGW-w64 g++（支持 C++11 或更高）**，在仓库根目录打开 PowerShell：

```powershell
New-Item -ItemType Directory -Force build | Out-Null
g++ -std=c++11 -finput-charset=GBK -fexec-charset=GBK Experiment11.cpp -o build/lexer.exe
g++ -std=c++11 -finput-charset=GBK -fexec-charset=GBK Experiment2.cpp -o build/predictive.exe
g++ -std=c++11 -finput-charset=GBK -fexec-charset=GBK Experiment4.4.cpp -o build/rpn.exe
```

终端中文显示需与程序输出编码一致。`Experiment3.cpp` 保留了 `freopen_s` 调用，需支持该接口的 Windows 工具链，不能据此声称 Linux 可构建。PL/0 的 `Makefile.win` 已移除原机器上的安装路径，使用当前编译器的搜索路径。

## 运行样例

### 词法扫描

运行 `./build/lexer.exe`，按提示输入 `eg1.txt`。程序先显示输入，再逐项输出词法识别结果。`eg1.txt` 含有用于观察错误处理的字符，不代表全部输入应被接受。

### 预测分析

运行 `./build/predictive.exe`，依次输入：

```text
12.txt
N
a #
```

`12.txt` 是文法输入；产生式右侧的符号用空格分隔，`#` 表示空串或输入结束标记。输出包含非终结符表、FIRST / FOLLOW / SELECT 集、预测分析表及分析步骤。需要保存输出时将第二项改为 `Y`，再指定新的输出文件名。

### 逆波兰表达式

在仓库根目录运行 `./build/rpn.exe`，程序固定读取 `4.4input.txt` 并覆盖 `4.4output.txt`。

| 输入 | 预期输出 |
| --- | --- |
| `(a+b)/c` | `ab+c/` |
| `(a+b)+(c+d)` | `ab+cd++` |

课程实现按单个字母/数字识别操作数，不支持多位数字、一元运算或完整错误恢复。原实现的运算符比较读取未填充的优先级表，括号未明确分组的表达式可能转换错误；上表仅演示当前两组有括号输入的转换流程，不代表一般表达式均正确。本次公开整理保留原算法，修复与回归测试留待后续完成。
